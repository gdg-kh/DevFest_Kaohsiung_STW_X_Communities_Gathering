## 13. 開發階段與任務對照

施工提示詞在另一份文件 `gdgkh-2026-build-prompts.md`，共 27 個任務。

| 階段 | 任務 | 內容 |
|---|---|---|
| 資料 | T01–T02 | config.json 與 content.json 假資料 |
| 樣式 | T03–T04 | 設計 token、基礎樣式 |
| 核心 | T05–T07 | i18n、store、dom |
| 元件 | T08–T09D | 詳細彈窗、卡片、圖片檢視器、感謝票、行事曆 |
| 區塊 | T10–T14E | 講者、議程與地圖、工作人員、感謝與擺攤、虛擬會場、活動介紹、首頁卡片、免費票、報名、跑馬燈 |
| 外殼 | T15–T17B | 導覽與溢出選單、GA、首頁與骨架、404 |
| 後台 | T18–T20 | 骨架、表單引擎、驗證與預覽 |
| 產生器 | T21–T22 | 類型設定表與 OG 繪圖、分享頁與 sitemap |

建議順序：先做 T01–T09D 打好地基（這些沒有 UI 也能驗），
再一次做完區塊層，最後做後台與產生器。
後台可以延後——手改 JSON 也能上線，後台是為了讓你之後改得舒服。

## 14. 決策紀錄

規格會變，但**理由不留下來，後人就會把它改回去**。
下表按時間記錄每次規格變更與背後的原因。
要推翻某條決定之前，先確認它當初的理由是否還成立。

### D01 · 不沿用 2025 的內部設計
2025 是逐年加功能疊出來的：資料散在 JSON 與 `main.js` 兩處、
六支高度重複的產生腳本、語言代碼在 JSON 用 `zh` 但在 JS 用 `zh-Hant`。
只繼承 repo 層級設定（CNAME、eslint、CI、canvas 套件），`/2026/` 內部全部重寫。

### D02 · 語言鍵全站統一 `zh-Hant`
2025 有兩套代碼要互轉，是 bug 溫床。統一成一套，沒有轉換層。

### D03 · 單一 `id`，不另設 slug
2025 是 `spk_001` 加一個 slug 的雙軌制，兩邊要同步。
2026 每筆只有一個 `id`（小寫底線），同時是網址、圖片檔名與關聯鍵。

### D04 · JSON 不存圖片路徑
路徑由 `id` 與類型推導。多一個欄位就多一個會不同步的地方。

### D05 · 選舉風強度為「混合玩梗」
版面骨架現代乾淨（議程要好讀），梗放在文案與微互動。

### D06 · 三語架構齊備但內容先做中文
`languages[].enabled` 控制顯示，翻完改成 `true` 即可上線，不用改程式。

### D07 · 議程軌道做成彈性
軌道數由 `tracks` 陣列長度決定，1 軌單欄、2–3 軌分欄、4 軌以上橫向捲動。
決定要開第二會場時只需改 JSON。

### D08 · 分享頁必須是實體 HTML
FB、LINE、X 的爬蟲不執行 JavaScript。SPA 的 hash route 分享出去，
每個講者的預覽圖與標題會全部一樣。

### D09 · 主辦單位不做分享頁
沒有人會單獨分享主辦單位連結，要分享會分享活動首頁。
分享類型因此從五種減為四種。主辦單位改成首頁卡片加詳細彈窗。

### D10 · 「去年頁面」與「主辦單位」移出導覽列
選單十項在小解析度會換行。這兩項瀏覽頻率低，
但放頁尾是死角，所以改成首頁快速入口卡片。

### D11 · 導覽列用量測式溢出選單保證單行
不靠縮小字體：中文低於 13px 難讀，而且**英日文標籤比中文長得多**
（「特別感謝」對上 Special Thanks），任何寫死的斷點都撐不過切語言。
改用 `ResizeObserver` 逐項量測，放不下的移進「更多」。桌機門檻同時提高到 1280px。

### D12 · 虛擬會場提早開放，不做時間狀態機
定位是「另一種取得場地資訊的方式」，不是活動當天限定。
省掉活動前／中／後三種狀態的判斷。

### D13 · 虛擬會場不做 iframe 嵌入
這類服務多半設有 `X-Frame-Options` 或 CSP `frame-ancestors`；
就算能嵌，WebRTC 的攝影機麥克風權限在 iframe 內容易失敗。
保留 `embed` 開關但預設關閉，實測確認可嵌再打開。

### D14 · 報名做成兩張並排的路徑卡
免費票要人工審核後寄碼，符合資格的人若先買票就得退票重來。
提醒必須出現在購票動作**之前**，而且不能是不起眼的小字。
兩張卡視覺權重相當，沒有資格的人不該覺得走錯路。

### D15 · 優惠碼絕不出現在網站上
靜態站沒有權限控管，寫進 JSON 或 HTML 就等於公開。
發放一律走表單回覆信或人工寄送。

### D16 · 跑馬燈與感謝區塊共用「感謝票」元件
原本兩處是不同視覺。改成同一張選票後，
使用者在跑馬燈看到的票、滾到下面又看到同一張票排成計票板，認知連貫。
擺攤維持 logo 卡片——攤位是參與者不是投票者。

### D17 · 跑馬燈速度用 px/s 而非「幾秒跑一圈」
固定秒數的話，贊助商從 5 家變 20 家時速度會暴增。
改成固定 px/s，動畫時間由程式算，贊助商增加只是週期變長。

### D18 · 贊助商不做大小分級
逐筆 `marquee` 開關控制是否上跑馬燈（群組篩選處理不了個別例外）。
所有票一樣大，層級差異只用票頭右側的「票種」文字表示。

### D19 · 配色一律用 GDG 官方色票
GDG 是 Google 官方社群品牌，hex 必須精確。
原本規劃的 `#FBBC04`（黃）、`#101010`（黑）、`#FAF7F0`（暖米白）全是錯的或自創的，
正確值是 `#f9ab00`、`#1e1e1e`、`#f0f0f0`。紙張質感改用噪點與硬邊陰影達成，不動 hex。

### D20 · 字體採混合策略
內文用系統字體堆疊（省流量、更原生），標題載一支顯示字體（保住品牌識別）。
原本規劃的 Archivo Black / Anton 撤掉——GDG 要求主字體是 Google Sans。

### D21 · 中文字重上限 700
**這條最容易被誤改。** 中文系統字體在各平台不同：
Mac 是蘋方、Windows 是微軟正黑、Android 是 Noto Sans CJK，
而**微軟正黑沒有 Black 字重**，寫 `font-weight: 900` 會觸發假粗體，
大字級的中文標題在 Windows 上會糊掉，但在 Mac 上看起來完全正常。
標題的份量改用色塊反白、粗外框、硬邊陰影達成。

### D22 · 不載入任何中文 webfont
中文字型檔動輒數 MB，是效能預算的最大威脅。中文一律使用系統既有字體。
（OG 圖產生器是伺服器端繪圖，那裡才需要實體字型檔，與前端無關。）

### D23 · 不做臨時公告區
活動當天現場宣布即可，使用者不會一直看網站。

### D24 · 不做議程搜尋篩選
場次數量不需要。

### D25 · 載入中用骨架而非 spinner
spinner 只說「在等」，骨架同時說明「等一下會出現什麼、大概多少」，
而且資料到達時版面不會跳動（CLS）。骨架寫在 HTML 裡，不等 JS 就顯示。

### D26 · 議程不做分享頁（2026-08-02 拍板）
維持四種分享類型：`speakers` / `staff` / `thanks` / `booths`。
理由：議程可從講者分享頁連過去，單獨分享議程的意義不高。
新增第五種類型會讓 T21 / T22 的 `ENTITY_TYPES` 多維護一組 OG 版型與 schema，成本大於效益。
要改：新增前先確認社群實際有「先分享議程再認識講者」的行為模式。

### D27 · 講者保留 `org`（公司）與 `title`（職稱）欄位（2026-08-02 拍板）
**推翻本文件先前預設「不做」的規劃。**
理由：使用者評估後認為 2025 的欄位在資訊呈現上有用（能一眼看出隸屬），
若塞進 `bio` 反而佔篇幅、不好排版。
影響：T02 `content.speakers[]` 新增兩個 `I18nText` 欄位；
T10 講者卡與 T21 OG 圖 person 版型需顯示（或明確不顯示）這兩欄；
資料模型（`02-data-model.md`）與 T02 施工單需同步更新。
要改：若「大部分講者的公司職稱其實填不出來或過時」，改回不做。

### D28 · 購票平台 URL 暫用佔位（2026-08-02 拍板）
`config.menu[].url`（`id: ticket`）先寫 `https://example.com/ticket`。
理由：購票平台尚未定案。
不改程式，只改 JSON 一個字串即可上線。
決定平台後（KKTIX、Accupass 或其他），直接改 config.json。

### D29 · 場地資訊擴展 `site` schema（2026-08-02 拍板）
場地：**KO-IN 智高點**
地址：800 高雄市新興區中正三路 25 號
Google Map：`https://maps.app.goo.gl/tsrtSkCcmjxoYs4cA`

`config.site` 新增兩個欄位：
- `venueAddress`（I18nText）— 地址（可含郵遞區號）
- `venueMapUrl`（string）— Google Map 分享短網址

理由：地址與地圖 URL 是使用者實際會用到的功能（複製地址、點開導航），
塞進 `venue`（I18nText）會混淆語意。多兩個欄位好過寫死在程式或 HTML 裡。
影響：`02-data-model.md` 需同步；使用場地資訊的區塊（Hero、首頁、地圖）都從 `site.venue*` 讀取。

### D30 · 假資料規模：10+ 講者、一日議程、雙軌（2026-08-02 拍板）
T02 content.json 假資料以此規模建立，讓 T11（議程時間軸）與 T09D（行事曆）
在雙軌情境下就先驗到分欄版面。
理由：小規模假資料容易漏掉「多軌並行」邊角情境，等到真實資料進來才發現不好看就晚了。

### D31 · GA4 沿用 2025 property `G-BMV35Q9F1G`（2026-08-02 拍板）
`config.analytics.ga4Id` 直接寫入該 ID，不再依 T01 施工單「留空字串」預設。
理由：跨年度共用 property 才能做流量比較與長期趨勢分析。
要改：若使用者建立獨立 2026 property，直接改 JSON 一個字串即可。

### D32 · 顯示字體先用 Google Sans Flex（2026-08-02 拍板）
T04 基礎樣式先接 Google Fonts 上公開可用的 Google Sans Flex。
理由：GDG 品牌資源包的 Google Sans 字型檔取得狀態未定，先不阻塞開發。
要改：拿到官方字型檔後放到 `2026/assets/fonts/`，把 T04 的 `@font-face` 改成本地載入。
